    4 Sealing, the chain, and the manifest

    1. Seal. When something significant happens, the system writes it into the record and seals it. Sealed means it cannot be quietly rewritten later.
    2. Chain. Each seal is linked to the seal before it. Change one entry and every link after it fails its check.
    3. Manifest. The whole system can be exported as one package with a manifest: every file listed with its fingerprint, so anyone can check, file by file, that what they hold is exactly what was sealed.
    4. Plug in anywhere. The record layer sits underneath the model, not inside it, so it can sit underneath other systems too, whichever model is on top.

    Other systems are adding record-keeping like this onto their systems now, as an afterthought. This system was built with it at the core, from the first day, because it exists to protect what people create.
